# UI rules (src/)

- The chat composer uses AI Elements PromptInput primitives; its existing file-routing callbacks remain separate from the primitive's attachment collection. Why: preserves ZIP/conversion behavior while sharing accessible input and submission controls.
- Speech text is joined through the browser-safe appendTranscript helper, with regression tests alongside existing tests. Why: preserves typed text and whitespace across recognition updates without coupling transcription to a service.
- Drawer uses AppDrawerView in the persistent NavigationGestures overlay; protected /drawer stays a direct entry. Search is inline. Why: preserves mounted pages and streams with one drawer/search UI.
- Incognito uses a dedicated route and workspace-only React state, bypassing history writes, background jobs, and persistent AI generators. Why: temporary messages and attachments must never reach browser storage; replies come from the stateless /api/chat route.
- Picture/video creation pages are retired: /images and /videos (and their chat URLs) are thin legacy redirects to /chat. Why: Vision is a text-output system; media is only format-converted, never generated or edited.
- Deep Thinking replies render as intro note → slim status card (stage + timer) → large title + structured Markdown, driven by `ChatMessage.deep`; the stage is persisted only once done. Why: users see live progress while the answer is verified server-side, and reloads never show a stuck spinner.
- Sidebar feature links share SidebarFeatures, secondary collection pages share WorkspaceShell, and Library reuses Search filtered to assets. Why: keeps navigation and stored-item discovery consistent.
- Projects use user-scoped workspace_projects through the existing local backend adapter, with creation in a separate view and shared icon definitions. Why: preserves browser-local persistence and consistent icons across creation and listing.
- Library derives applicable file-type filters from the shared search index metadata. Why: avoids separate storage and keeps Search and Library classifications consistent.
- The chat screen is mounted once by the `/chat` layout route (`src/routes/chat.tsx`); `/chat/`, `/chat/$chatId` and `/chat/incognito` render nothing and only set address/title, and the page reads the chat id from the pathname. Why: separate leaf routes remounted the whole screen when a new chat got its address, which looked like a reload and dropped the live reply.
- Route errors use the shared `components/route-error` as the router default, and failed page-file downloads retry in place (3 tries) before the published-only single reload. Why: keeps the open screen intact instead of full-page reloads.
- Chat mode is per conversation, owned by ChatWorkspace and saved through `lib/chat-mode-store` (a pre-send draft is adopted by the new chat; incognito stays in memory). Why: a mode must stay on across replies, navigation and reloads until the user turns it off.
- Swipe routing is decided by `gestureSurface`/`swipeAction` in `lib/navigation-motion` (Chat ↔ drawer/Projects, drawer pages → drawer), and drawer pages open with `__visionDirection: "left"`. Pull-down (top→down) on Chat or the App Drawer opens Search via `requestSearch`/`DRAWER_SEARCH_EVENT`, reusing the drawer's animated morph. Why: one tested rule set for gestures and their matching transition direction.

- Chat replies share one Markdown renderer and all fenced content uses CodeBlock as its frame, toolbar and expanded viewer; Markdown keeps rendered content and clean rich copying, text stays literal, and programming fences keep syntax highlighting. Format labels remain visible at every size. Why: one UI prevents copy-block styles diverging while preserving each content type.
- Chat Markdown tables use `components/chat/table-reply` with original-source copying, stable view-only sorting and formula-safe CSV exports from `lib/table-export`. Why: multiple tables remain independent and spreadsheet downloads cannot execute cell formulas.
- Code blocks/previews share the accessible full-screen numbered viewer and sandboxed preview; media queries hide desktop tools on mobile; frames never get same-origin privileges. Why: shared capabilities without generated-code access to the app.
- Shared content-block height follows natural rendered content and is capped using inline container units; ResizeObserver only detects clipped content for its fade. Why: short replies stay compact while streaming and wrapped Markdown resize without text-length guesses or font shrinking.
- NavigationGestures preserves Outlet and shares panel motion for App Drawer and Projects (taps: Web Animations; swipes: finger then spring); drawer children animate only during inline Search morphs, never on panel entrance. Projects pull-down targets its own view first. Why: a single entrance avoids stacked scaling/bounce while preserving streams.
